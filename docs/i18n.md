# Internationalisation

**Tout est traduisible dès la V1** : aucun texte visible en dur (contenu, `aria-label`,
`title`, `alt`, `placeholder`, textes des badges, messages d'état).

## Fichiers

```
src/locales/
  fr/            référence
    common.json  marque, valeurs de l'API (veracity_*, badge_category_*, context_need_*,
                 report_reason_*), langues, erreurs TWR-…
    content.json textes affichés dans X (préfixe content_)
    popup.json   préfixe popup_
    options.json préfixe options_
  en/            mêmes fichiers, mêmes clés
```

Format Chrome : `{"clé": {"message": "…", "description": "contexte pour la traduction"}}`.
Au build, les fichiers d'une langue sont fusionnés dans `_locales/<lang>/messages.json`
(clé en double = erreur), ce qui fournit aussi le nom et la description traduits du
manifeste (`__MSG_extName__`). `default_locale` : `en`.

## Module de traduction (`src/shared/i18n.ts`)

`chrome.i18n` suit la langue du navigateur et ne se change pas à l'exécution. Or la
langue est **au choix de l'utilisateur**. Les catalogues sont donc embarqués dans le
code (mêmes fichiers source) et résolus ainsi :

langue choisie → anglais → `chrome.i18n.getMessage` → libellé générique.

```ts
const t = createTranslator(settings.language);   // "auto" | "fr" | "en"
t.t("popup_status_active");
t.tp("popup_sent_today", 12);                     // clés _one / _other via Intl.PluralRules
t.enumLabel("veracity", claim.veracity);          // veracity_false, sinon veracity_unknown
t.errorLabel("TWR-BDG-019");                      // error_TWR_BDG_019, sinon error_generic
t.date(iso, { timeStyle: "short" }); t.number(1200);
```

Règles :

- **Valeurs de l'API → libellés** : l'API renvoie des valeurs stables, jamais des
  libellés. Une valeur inconnue affiche le libellé générique, jamais la valeur brute.
- **Pas de concaténation** de morceaux de phrase : substitutions `$1`…`$9`.
- **Pluriels, dates, nombres** par `Intl`, dans la langue choisie.
- **Contenu serveur** inséré avec son attribut `lang` et `dir="auto"`.
- La langue choisie est aussi envoyée dans `lang` des verdicts ; si la note revient
  dans une autre langue (`note.lang`), l'interface l'indique.

## Ajouter une langue

1. Copier `src/locales/en/` vers `src/locales/<code>/` et traduire.
2. Ajouter le code à `SUPPORTED_LANGS` (`src/shared/constants.ts`) et la clé
   `language_<code>` (nom de la langue dans sa propre langue) à tous les `common.json`.

Aucune autre modification de code.

## Tests

`test/i18n.test.ts` vérifie que toutes les langues ont exactement les mêmes fichiers et
les mêmes clés, les mêmes substitutions, des noms de clés valides pour Chrome, et
recherche les chaînes visibles en dur dans `src/content`, `src/popup`, `src/options`,
`src/pages`.
